요청하신 Golden Master 회귀 테스트를 현재 C++/Google Test 구조에 맞춰 설계하고 구현하겠습니다. 먼저 기존 CMake, 테스트, TextTestFixture 구성을 확인해서 출력 파일을 어디에 두고 어떻게 실행하는 게 자연스러운지 보겠습니다.

기존 규칙 파일을 보니 “동작 보존을 위한 테스트 우선” 흐름이 중요하고, `TextTestFixture` 출력이 Golden Master로 잘 맞습니다. 이제 실제 테스트 파일과 CMake 타깃을 확인한 뒤 fixture를 재사용 가능한 방식으로 분리하겠습니다.

구현 방향은 소스 아래 `cpp/test/approval/`에 승인된 출력(`*.approved.txt`)을 보관하고, 테스트 실패 시 빌드 디렉터리에 실제 출력(`*.received.txt`)을 남기는 방식으로 잡겠습니다. 파일 경로는 CMake가 테스트 바이너리에 주입해서 Windows와 CI에서 같은 코드가 돌도록 만들겠습니다.

이제 Golden Master 테스트 코드는 들어갔고, 승인 파일은 테스트 자체의 업데이트 모드로 생성하겠습니다. 먼저 새 타깃이 Windows/CMake에서 정상 컴파일되는지 확인한 뒤 같은 바이너리로 `approved` 파일을 만들겠습니다.

현재 PowerShell이 `&&` 체인을 지원하지 않는 버전이라 빌드 명령만 PowerShell 문법으로 다시 실행하겠습니다.

승인 파일 생성까지 확인했습니다. 다음으로 CI에서 동일한 `cmake --build`와 `ctest` 경로를 자동 실행하도록 GitHub Actions 워크플로를 추가하겠습니다.

테스트 코드, 승인 파일, CMake, CI 워크플로까지 들어갔습니다. 이제 전체 CTest를 실행해서 기존 단위 테스트와 Golden Master가 함께 통과하는지 확인하겠습니다.

완료했습니다.

변경 사항:
- `cpp/test/GildedRoseApprovalTest.cpp`
  - `TextTestFixture` 기반 30일 시뮬레이션 출력 생성
  - `approved` 파일과 비교
  - 실패 시 `cpp/build/approval/gilded_rose_30_days.received.txt` 생성
  - `GILDED_ROSE_APPROVAL_UPDATE=1`일 때 승인 파일 갱신
- `cpp/test/approval/gilded_rose_30_days.approved.txt`
  - 현재 동작 기준 Golden Master 보관
- `cpp/CMakeLists.txt`
  - `gilded_rose_approval_test` 타깃 추가
  - `gtest_discover_tests()`로 ctest 통합
- `.github/workflows/cpp.yml`
  - GitHub Actions에서 configure/build/ctest 자동 실행

실행 방법:

```powershell
cmake -S "cpp" -B "cpp/build"
cmake --build "cpp/build"
ctest --test-dir "cpp/build" --output-on-failure
```

승인 파일 재생성:

```powershell
$env:GILDED_ROSE_APPROVAL_UPDATE = "1"
ctest --test-dir "cpp/build" -R "TextTestFixture" --output-on-failure
Remove-Item Env:\GILDED_ROSE_APPROVAL_UPDATE
```

검증 결과: `ctest --test-dir "cpp/build" --output-on-failure` 기준 26개 테스트 모두 통과했습니다. IDE linter는 Google Test include 경로를 못 찾는 clangd 진단을 냈지만, CMake 빌드와 테스트는 정상입니다.
