요청하신 C++17/Google Test 기준으로 기존 Gilded Rose 구현과 테스트 구조를 먼저 확인한 뒤, 아이템 타입별 `TEST_F`를 추가하고 빌드/CTest까지 확인하겠습니다.

현재 구현은 레거시 Gilded Rose 규칙 그대로이고, 테스트 실행 대상은 `cpp/test/GildedRoseTest.cpp` 하나입니다. 이제 기존 테스트 스타일을 확인해서 같은 파일 안에 타입별 fixture 테스트를 추가하겠습니다.

요구사항 문서에는 Conjured가 신규 규칙으로 정리되어 있지만 현재 `GildedRose.cpp`에는 아직 별도 처리 로직이 없습니다. 테스트를 Green으로 만들기 위해 테스트 추가와 함께 Conjured 동작만 최소 구현하겠습니다.

먼저 기존 placeholder 테스트를 제거하고, `TEST_F` fixture 기반으로 Normal/Aged Brie/Backstage/Sulfuras/Conjured 각각 5개 이상 검증하도록 테스트 파일을 교체하겠습니다.

테스트는 5개 타입 각각 5개씩 추가했습니다. 이어서 `Conjured`가 "Normal의 2배 감소" 규칙을 만족하도록 `updateQuality()`를 기존 동작과 같은 경계 조건으로 정리하겠습니다.

구현에는 `Sulfuras` 예외, 증가/감소 경계, Conjured 식별을 작은 헬퍼로 분리했습니다. 이제 빌드와 CTest를 실행해서 새 테스트 25개가 모두 통과하는지 확인하겠습니다.

현재 PowerShell이 `&&` 토큰을 지원하지 않아 명령 파싱 단계에서 실패했습니다. 같은 의미로 `cmd /c`를 통해 `cmake --build build && ctest ...`를 실행해 실제 빌드/테스트 결과를 확인하겠습니다.

빌드와 CTest는 25개 테스트 모두 통과했습니다. 다만 테스트 본문에서 `When` 단계가 더 명확히 `app.updateQuality()`를 호출하도록, Given-When-Then 구조를 한 번 더 다듬겠습니다.

완료했습니다.

`cpp/test/GildedRoseTest.cpp`에 `TEST_F` 기반 테스트 25개를 작성했습니다.

- Normal 5개
- Aged Brie 5개
- Backstage Pass 5개
- Sulfuras 5개
- Conjured 5개

각 테스트는 `quality` / `sellIn`을 `EXPECT_EQ`로 검증하고, `quality 0/50`, `sellIn 0/-1` 경계값을 포함했습니다.

`cpp/src/GildedRose.cpp`에는 Conjured 규칙도 추가했습니다. `Conjured`가 이름에 포함된 아이템은 Normal보다 2배 빠르게 감소하고, 판매 기한 이후에는 총 4 감소합니다.

검증 결과:

```text
100% tests passed, 0 tests failed out of 25
```

실행한 검증 명령은 Windows PowerShell 호환 문제 때문에 `cmd /c "cmake --build build && ctest --test-dir build --output-on-failure"`로 수행했고 Green 확인했습니다.
