# Gilded Rose CTest 결함 분석 작업 보고서

## 1. 작업 목적

본 보고서는 C++17 및 Google Test 기반 Gilded Rose 프로젝트에서 `ctest` 실패 로그 기반 결함 분석 요청에 대해 현재 코드와 테스트 상태를 확인한 결과를 기록한다.

요청 범위는 다음과 같았다.

- `EXPECT_EQ` 실패의 기대값과 실제값 차이 요약
- `GildedRose::updateQuality()` 버그 위치 특정
- 결함 심각도 분류
- `Item` 구조체를 수정하지 않는 최소 변경 수정 방안 제안
- 수정 diff 제안 및 `cmake --build build && ctest` Green 확인 절차 제시

## 2. 확인 대상

다음 파일과 문서를 확인했다.

- `cpp/src/GildedRose.cpp`
- `cpp/test/GildedRoseTest.cpp`
- `cpp/include/GildedRose.h`
- `docs/requirements_analysis.md`
- `.cursorrules`

## 3. 분석 결과

사용자 요청에는 실제 `ctest` 실패 로그가 포함되어 있지 않았다.

따라서 특정 `EXPECT_EQ` 실패 지점의 기대값과 실제값 차이는 산출할 수 없었다. 대신 현재 저장소의 구현과 테스트를 기준으로 재현 여부를 확인했다.

`GildedRose::updateQuality()`는 현재 다음 주요 규칙을 처리하고 있다.

- `Sulfuras, Hand of Ragnaros`는 `sellIn`과 `quality`를 변경하지 않음
- `Aged Brie`는 시간이 지날수록 `quality` 증가
- `Backstage passes to a TAFKAL80ETC concert`는 남은 날짜에 따라 `quality` 증가량이 달라지고, 만료 후 0이 됨
- `Conjured` 문자열이 포함된 아이템은 Normal 아이템보다 2배 빠르게 `quality` 감소
- 감소형 아이템의 `quality`는 0 미만으로 내려가지 않음
- 증가형 아이템의 `quality`는 50을 초과하지 않음

## 4. 재현 및 검증 결과

다음 명령을 실행해 현재 빌드와 테스트 상태를 확인했다.

```powershell
cmake --build build; if ($LASTEXITCODE -eq 0) { ctest --test-dir build --output-on-failure }
```

실행 위치는 `cpp` 디렉터리였다.

검증 결과는 다음과 같다.

```text
100% tests passed, 0 tests failed out of 25
```

현재 기준으로는 `EXPECT_EQ` 실패가 재현되지 않았다.

## 5. 결함 심각도

분류: `Info`

근거는 다음과 같다.

- 실제 실패 로그가 제공되지 않아 기대값과 실제값의 차이를 특정할 수 없음
- 현재 `GildedRoseTest` 25개 테스트가 모두 통과함
- `updateQuality()`에서 현재 테스트로 재현 가능한 기능 결함이 확인되지 않음
- 사용자에게 실패 로그 제공 시 추가 분석이 필요하다고 안내함

## 6. 수정 diff 제안

현재 재현 가능한 결함이 없어 소스 코드 수정 diff는 제안하지 않았다.

`Item` 구조체 역시 수정하지 않았다.

실제 실패 로그가 제공될 경우, 다음 순서로 최소 변경 수정안을 도출한다.

1. 실패한 테스트명과 `EXPECT_EQ` 메시지에서 기대값과 실제값을 비교한다.
2. 실패 아이템 타입과 경계값 조건을 식별한다.
3. `cpp/src/GildedRose.cpp`의 해당 분기 위치를 특정한다.
4. 기존 헬퍼 함수와 분기 구조를 유지하면서 최소 변경으로 수정한다.
5. 동일 케이스의 회귀 테스트를 추가하거나 기존 테스트 기대값을 검증한다.
6. `cmake --build build` 및 `ctest --test-dir build --output-on-failure`를 다시 실행한다.
