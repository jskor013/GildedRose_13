# Gilded Rose C++17 프로젝트 Cursor AI 규칙 설계 보고서

## 1. 작성 목적

본 보고서는 Gilded Rose C++17 레거시 코드베이스에서 Cursor AI가 일관된 기준으로 QA와 리팩토링을 수행하도록 프로젝트 루트에 `.cursorrules` 파일을 작성한 내용을 정리한다.

Gilded Rose는 도메인 규칙이 코드에 강하게 묶여 있는 레거시 카타 특성이 있으므로, AI가 임의로 구조체를 변경하거나 기존 동작을 훼손하지 않도록 명확한 작업 경계를 정의하는 것이 중요하다.

## 2. 적용 대상

- 프로젝트 루트의 `.cursorrules`
- C++17 기반 Gilded Rose 구현 코드
- CMake 빌드 설정
- Google Test 기반 테스트 코드
- gcov/lcov 기반 커버리지 확인 작업

## 3. 핵심 설계 원칙

### 3.1 기술 스택 명시

프로젝트의 기본 기술 스택을 C++17, CMake, Google Test, gcov/lcov로 고정했다. 이를 통해 AI가 다른 테스트 프레임워크나 빌드 방식을 임의로 도입하지 않도록 제한한다.

### 3.2 절대 도메인 규칙 보호

Gilded Rose의 핵심 불변 조건을 절대 규칙으로 정의했다.

- `Item` 구조체는 수정하지 않는다.
- `quality`는 `Sulfuras`를 제외하고 항상 0 이상 50 이하를 유지한다.
- `Sulfuras`는 `sellIn`과 `quality`가 변하지 않는다.
- `sellIn` 음수 값은 유효한 상태로 허용한다.

이 규칙은 레거시 코드 리팩토링 중 API 계약과 기존 요구사항을 보존하기 위한 안전장치다.

### 3.3 테스트 우선 리팩토링

리팩토링은 테스트가 Green 상태일 때만 진행하도록 규정했다. 또한 테스트는 Given-When-Then 의도가 드러나도록 작성하고, fixture가 필요한 경우 `TEST_F`를 사용하도록 했다.

필수 경계값으로는 다음을 포함했다.

- `quality == 0`
- `quality == 50`
- `sellIn == 0`
- `sellIn == -1`

이 경계값은 품질 하한/상한과 판매 기한 전후 동작을 검증하기 위한 최소 기준이다.

### 3.4 안전한 리팩토링 기준

동작 변경과 구조 개선을 분리하고, 매직 넘버는 의미 있는 상수로 추출하도록 권장했다. 이는 코드 가독성을 높이면서도 기존 동작을 보존하기 위한 방식이다.

## 4. 기대 효과

- AI가 `Item` 구조체를 임의로 변경하는 위험을 줄인다.
- `quality`와 `sellIn` 관련 도메인 불변 조건을 지속적으로 유지한다.
- 테스트가 부족한 상태에서 리팩토링이 진행되는 것을 방지한다.
- 경계값 테스트를 통해 Gilded Rose의 주요 결함 가능 지점을 사전에 확인한다.
- C++17, CMake, Google Test 중심의 프로젝트 일관성을 유지한다.

## 5. 산출물

다음 파일을 생성했다.

- `.cursorrules`

해당 파일은 Cursor AI가 프로젝트 작업 시 따라야 할 기술 스택, 도메인 불변 조건, 테스트 작성 기준, 리팩토링 원칙을 정의한다.
