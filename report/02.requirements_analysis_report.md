# Gilded Rose C++17 요구사항 분석 보고서

## 1. 작성 목적

본 보고서는 `GildedRoseRequirements.txt`와 `README.md`에 정의된 Gilded Rose 도메인 요구사항을 C++17 구현 및 Google Test 검증 관점에서 재정리한 내용을 요약한다.

Gilded Rose는 아이템 이름 문자열에 따라 비즈니스 규칙이 달라지는 레거시 카타이므로, 구현 전 아이템 타입별 규칙과 경계값, 예외 조건을 명확히 정의하는 것이 중요하다.

## 2. 적용 대상

- `cpp/src/GildedRose.cpp`의 `updateQuality()` 구현
- `cpp/include/Item.h`의 기존 `Item` 클래스 계약
- Google Test 기반 단위 테스트
- 신규 `Conjured` 아이템 요구사항
- `quality`와 `sellIn` 관련 경계값 검증

## 3. 핵심 분석 내용

### 3.1 아이템 타입별 규칙 정리

요구사항을 Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 다섯 가지 타입으로 분류했다.

| 아이템 타입 | 핵심 동작 |
| --- | --- |
| Normal | 매일 `sellIn` 1 감소, `quality` 1 감소, 판매 기한 경과 후 `quality` 2 감소 |
| Aged Brie | 매일 `quality` 증가, 판매 기한 경과 후 증가 속도 2배, 최대 50 유지 |
| Backstage Pass | 콘서트일이 가까워질수록 `quality` 증가량이 1, 2, 3으로 증가하고 콘서트 이후 0 |
| Sulfuras | `sellIn`과 `quality` 모두 변경 없음, `quality` 80 예외 허용 |
| Conjured | Normal 아이템보다 `quality`가 2배 빠르게 감소 |

이 분류를 통해 구현 시 각 아이템 타입의 분기 조건과 기대 결과를 독립적으로 검증할 수 있다.

### 3.2 문자열 비교 및 분기 위험

현재 C++ 구현은 `std::string`의 정확한 문자열 비교에 의존한다. 따라서 아이템 이름의 공백, 쉼표, 대소문자, 철자가 조금만 달라도 다른 타입으로 처리될 수 있다.

특히 `Conjured`는 신규 요구사항에서 카테고리처럼 표현되므로, `name == "Conjured"`로 정확히 비교할지 `name.find("Conjured") != std::string::npos`로 포함 여부를 볼지 테스트와 함께 정책을 고정해야 한다.

또한 `Sulfuras`는 어떤 감소 로직보다 먼저 예외 처리되어야 하며, 일반적인 `quality` 상한 50을 적용하면 안 된다.

### 3.3 예외 및 경계값 조건

핵심 경계값은 다음과 같이 정리했다.

- `quality == 0`: 감소형 아이템은 더 이상 감소하지 않아야 한다.
- `quality == 50`: 증가형 아이템은 더 이상 증가하지 않아야 한다.
- `sellIn == 0`: 업데이트 후 `-1`이 되며 판매 기한 경과 규칙이 적용된다.
- `sellIn == -1`: 유효한 음수 값이며 기한 경과 상태로 처리한다.
- `Sulfuras`: `quality == 80`을 유지하며 `sellIn`도 변하지 않는다.

이 조건들은 리팩토링이나 Conjured 기능 추가 중 회귀가 발생하기 쉬운 지점이다.

### 3.4 Conjured 신규 요구사항 명세

Conjured 아이템은 Normal 아이템의 2배 속도로 `quality`가 감소한다.

- 판매 기한 전: 하루에 `quality` 2 감소
- 판매 기한 후: 하루에 `quality` 4 감소
- `quality`는 0 미만으로 내려가지 않음
- `sellIn`은 Normal 아이템처럼 매일 1 감소

이 규칙은 기존 Normal 감소 로직을 단순 복사하기보다 감소율을 명시적으로 분리해서 테스트하는 것이 안전하다.

### 3.5 Google Test 시나리오 기준

테스트 시나리오는 아이템 타입별 정상 동작, 판매 기한 전후 동작, `quality` 하한/상한, `Sulfuras` 예외, `Conjured` 신규 규칙을 포함하도록 번호 목록으로 정리했다.

특히 다음 테스트는 필수로 다루어야 한다.

- Normal 아이템의 기본 감소 및 기한 경과 후 2배 감소
- Aged Brie의 증가 및 50 상한 유지
- Backstage Pass의 10일, 5일, 콘서트 이후 경계
- Sulfuras의 무변경 보장
- Conjured의 기본 2 감소, 기한 경과 후 4 감소, 0 하한 유지

## 4. 기대 효과

- C++ 구현 전 요구사항 해석 차이를 줄인다.
- 문자열 기반 분기에서 발생할 수 있는 오분류 위험을 사전에 드러낸다.
- `quality`와 `sellIn` 경계값을 기준으로 테스트 누락을 줄인다.
- `Conjured` 신규 요구사항의 감소율과 경계 조건을 명확히 검증할 수 있다.
- 향후 리팩토링 시 기존 동작과 신규 동작을 구분해 안전하게 변경할 수 있다.
