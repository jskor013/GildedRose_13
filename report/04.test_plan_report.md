# Gilded Rose 테스트 계획서 작성 작업 보고서

## 1. 작성 목적

본 보고서는 Gilded Rose C++17 프로젝트의 단위 테스트 계획서 작성 및 문서 위치 정리 작업 내용을 기록한다.

시니어 QA 리드 관점에서 `GildedRose::updateQuality()`의 주요 비즈니스 규칙, 경계값, 예외 조건, 커버리지 목표를 테스트 계획으로 구체화하는 것이 이번 작업의 목적이다.

## 2. 작업 범위

- `TEST_F` 기반 Google Test 단위 테스트 범위와 우선순위 정의
- `quality == 0`, `1`, `49`, `50` 경계값 테스트 케이스 정리
- `sellIn == 0`, `-1` 판매 기한 경계 테스트 케이스 정리
- Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 아이템별 테스트 범위 정리
- 예외 및 특이 케이스 목록 작성
- `gcov/lcov` 기반 커버리지 목표와 측정 및 개선 전략 작성
- 테스트 계획서를 루트에서 `docs/` 폴더로 이동

## 3. 산출물

다음 파일을 생성했다.

- `docs/test_plan.md`
- `report/04.test_plan_report.md`

`docs/test_plan.md`는 실제 테스트 작성 전에 사용할 테스트 계획 문서다. 기존 프로젝트 구조와 `cpp/CMakeLists.txt`의 Google Test 설정을 기준으로 작성했으며, 현재 placeholder 테스트를 `TEST_F` 기반 테스트로 대체하는 방향을 제시한다.

본 파일은 테스트 계획서 작성 작업의 목적, 범위, 산출물, GitHub 업로드 이력을 추적하기 위한 작업 보고서다.

## 4. 핵심 내용

테스트 계획서는 다음 검증 축을 중심으로 작성했다.

- 아이템 타입별 핵심 규칙: Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured
- 우선순위: P0, P1, P2, P3로 분리
- 경계값: `quality` 0/1/49/50, `sellIn` 0/-1
- 예외 조건: Sulfuras 품질 80 예외, 음수 `sellIn`, Backstage Pass 만료 처리, 문자열 식별 정책
- 커버리지 목표: 라인/브랜치 90% 이상, 함수 100%, 핵심 비즈니스 분기 100%
- 커버리지 측정: GCC 또는 MinGW 환경의 `gcov/lcov`, `genhtml` 활용 절차

## 5. GitHub 업로드 계획

이번 보고서와 테스트 계획서를 하나의 문서 작업 커밋으로 정리하여 GitHub 원격 저장소의 `prompting` 브랜치에 업로드한다.

커밋 대상은 이번 작업에서 생성한 문서 파일로 제한한다.

- 포함: `docs/test_plan.md`
- 포함: `report/04.test_plan_report.md`
- 제외: `build/` 빌드 산출물
- 제외: 이번 작업과 무관한 기존 미추적 파일
