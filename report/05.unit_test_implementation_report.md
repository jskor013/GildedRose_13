# Gilded Rose 아이템 타입별 단위 테스트 구현 작업 보고서

## 1. 작업 목적

본 보고서는 C++17 및 Google Test 기반 Gilded Rose 프로젝트에서 아이템 타입별 단위 테스트를 작성하고, 테스트가 통과하도록 필요한 구현을 보완한 작업 내용을 기록한다.

시니어 C++ QA 관점에서 Normal, Aged Brie, Backstage Pass, Sulfuras, Conjured 아이템의 핵심 비즈니스 규칙과 경계값을 `TEST_F` 기반 테스트로 고정하는 것이 이번 작업의 목적이다.

## 2. 작업 범위

- `cpp/test/GildedRoseTest.cpp`의 placeholder 테스트 제거
- Google Test fixture `GildedRoseTest` 추가
- 아이템 타입별 최소 5개 `TEST_F` 작성
- `quality == 0`, `quality == 50` 경계값 검증
- `sellIn == 0`, `sellIn == -1` 경계값 검증
- `EXPECT_EQ`를 사용한 `quality` 및 `sellIn` 결과 검증
- Given-When-Then 주석 구조 적용
- Conjured 아이템 규칙 구현
- CMake 빌드 및 CTest 실행 확인

## 4. 테스트 설계 내용

`cpp/test/GildedRoseTest.cpp`에는 총 25개의 `TEST_F` 테스트를 작성했다.

- Normal: 5개
- Aged Brie: 5개
- Backstage Pass: 5개
- Sulfuras: 5개
- Conjured: 5개

각 테스트는 하나의 규칙 또는 경계값을 검증하도록 구성했으며, 모든 테스트에 Given-When-Then 주석을 포함했다.

## 5. 구현 보완 내용

기존 `GildedRose::updateQuality()` 구현에는 Conjured 아이템 전용 규칙이 없었다.

이번 작업에서는 다음 동작을 추가했다.

- 이름에 `Conjured`가 포함된 아이템을 Conjured로 식별
- 판매 기한 전에는 Normal 아이템의 2배 속도로 `quality` 감소
- 판매 기한 후에는 하루에 총 4만큼 `quality` 감소
- `quality`가 0 미만으로 내려가지 않도록 보장

기존 특수 아이템 규칙도 명확히 유지했다.

- `Sulfuras, Hand of Ragnaros`는 `sellIn`과 `quality`가 변하지 않음
- `Aged Brie`는 시간이 지날수록 `quality` 증가
- `Backstage passes to a TAFKAL80ETC concert`는 콘서트 날짜가 가까워질수록 더 빠르게 증가하고, 만료 후 0이 됨

## 6. 검증 결과

다음 명령으로 빌드 및 테스트를 확인했다.

```bash
cmd /c "cmake --build build && ctest --test-dir build --output-on-failure"
```

검증 결과는 다음과 같다.

```text
100% tests passed, 0 tests failed out of 25
```

PowerShell 환경에서 `&&` 토큰이 지원되지 않아, 동일한 의미의 명령을 `cmd /c`로 실행했다.
